Dimensional Modeling & Architecture

How I structure clean, high-performance Star Schemas in Power BI to ensure single-direction filter propagation and sub-second calculation speeds.

Workforce Attrition Star Schema Architecture

Optimized for Drill-Down, Row-Level Security, & Fact Granularity
1-to-Many Relationships · Single Direction Filter
Dim_Department_Role [Dim]
  • DepartmentIDPK (1)
  • DepartmentNameText
  • JobRoleText
  • JobLevelInt
Fact_Employee_Monthly [Fact]
  • SnapshotIDPK
  • EmployeeNumberFK (∞)
  • DateKeyFK (∞)
  • DepartmentIDFK (∞)
  • MonthlyIncome₹ Measure
  • AttritionFlagBinary (0/1)
  • YearsAtCompanyNumeric
  • OverTimeHoursNumeric
Dim_Calendar [Dim]
  • DateKeyPK (1)
  • DateDate
  • FiscalYearText
  • FiscalQuarterText
  • IsWorkdayBoolean
Key Modeling Principle: All dimension tables filter the fact table via 1-to-Many (*) relationships with single-direction filtering. This eliminates circular dependencies, maintains referential integrity, and keeps DAX memory usage optimized in VertiPaq.

-- DAX Time Intelligence: YoY Headcount Variance
YoY Headcount Growth % = 
VAR CurrentHeadcount = COUNTROWS('Dim_Employees')
VAR PreviousYearHeadcount = 
    CALCULATE(
        COUNTROWS('Dim_Employees'),
        SAMEPERIODLASTYEAR('Dim_Calendar'[Date])
    )
RETURN
    DIVIDE(
        CurrentHeadcount - PreviousYearHeadcount,
        PreviousYearHeadcount,
        0
    )

-- DAX: Attrition Rate with Dynamic Denominator Context
Attrition Rate % = 
VAR TotalDeparted = 
    CALCULATE(
        COUNTROWS('Dim_Employees'),
        'Dim_Employees'[Attrition] = "Yes"
    )
VAR ActiveBase = COUNTROWS('Dim_Employees')
RETURN
    DIVIDE(TotalDeparted, ActiveBase, 0)
